Decomposição de Épico em Features de Solução

Portal de Autoatendimento de Negociação de Dívidas (Greenfield) - Bureau de Crédito

FT-01: Autenticação Segura & Verificação Cadastral

Complexidade de Engenharia Média
Prioridade de Negócio Crítica (Blocker)
Esforço Estimado 13 Pontos de Feature
Perfis Envolvidos SecOps, Backend, Frontend Svelte

1. Descrição do Escopo

Esta feature engloba todo o fluxo inicial de identificação, cadastro e autenticação de segurança do consumidor no portal. Por tratar de dados protegidos pelo sigilo bancário e LGPD, exige validação em duas etapas (2FA via SMS/E-mail) e verificação cadastral contra o banco de dados oficial do Bureau de Crédito (score/dados pessoais).

2. Histórias de Usuário

US-01.1 (Frontend) - Login Descomplicado por CPF

Como consumidor inadimplente,
Quero informar meu CPF e receber um código de validação rápida via SMS/E-mail,
Para que eu possa acessar minhas dívidas sem precisar decorar senhas complexas.

Cenário: Login bem-sucedido com envio de OTP (One-Time Password)
Dado que estou na tela de login do Portal de Autoatendimento
Quando digito um CPF válido cadastrado no Bureau de Crédito
E clico em "Receber Código de Acesso"
Então o sistema deve enviar um SMS/E-mail com código de 6 dígitos e exibir a tela de inserção do OTP.

US-01.2 (Backend) - Motor de Validação OTP e JWT

Como API do Portal de Autoatendimento,
Quero validar o código de acesso temporário enviado ao usuário e retornar um token de sessão criptografado (JWT),
Para garantir a segurança dos dados financeiros e impedir acessos não autorizados.

Cenário: Validação de OTP incorreta
Dado que o usuário recebeu o código OTP para o login
Quando ele enviar um código que não coincide com o gerado ou expirado (tempo > 5 min)
Então a API deve retornar um erro HTTP 401 (Unauthorized) e bloquear novas tentativas após 3 erros consecutivos.

3. Integrações de API & Mapeamento de Dados

{
  "cpf": "12345678901",
  "channel": "sms"
}

POST /api/v1/auth/verify-otp (Frontend -> Backend)

{
  "cpf": "12345678901",
  "otp_code": "482015"
}

Response (Success 200 OK):

{
  "authenticated": true,
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "name": "Ana Maria de Souza",
    "last_access": "2023-11-20T10:15:30Z",
    "score": 645
  }
}

FT-02: Painel Consolidador de Pendências

Complexidade de Engenharia Média
Prioridade de Negócio Crítica
Esforço Estimado 10 Pontos de Feature
Perfis Envolvidos Backend, Frontend Svelte, Designer UX/UI

1. Descrição do Escopo

Consiste no painel de controle principal do devedor (Dashboard) que carrega imediatamente após o login seguro. Consolida em tela única todos os débitos ativos indexados ao CPF cadastrado, agrupando por credor (Instituição Financeira, Varejo, Telecom), mostrando o montante original da dívida, dias de atraso e o desconto pré-aprovado para liquidação rápida.

2. Histórias de Usuário

US-02.1 (Frontend) - Listagem de Dívidas Amigável

Como consumidor inadimplente,
Quero visualizar minhas dívidas em formato de cartões limpos e fáceis de compreender,
Para que eu saiba exatamente o total pendente e quais credores oferecem os maiores descontos de forma transparente.

US-02.2 (Backend) - Agregador de Carteiras de Credores

Como API do Portal de Autoatendimento,
Quero consultar o banco de dados interno de restrições de crédito sincronizado com as carteiras dos credores parceiros,
Para consolidar as dívidas elegíveis à negociação do CPF autenticado.

FT-03: Motor Simulador de Acordos & Negociação Interativa

Complexidade de Engenharia Alta
Prioridade de Negócio Crítica
Esforço Estimado 21 Pontos de Feature
Perfis Envolvidos Matemático Financeiro, Backend, Frontend Svelte (Slider/UX)

1. Descrição do Escopo

O coração do sistema. Permite que o usuário, após selecionar uma das pendências elegíveis, simule opções de liquidação de forma dinâmica. O usuário pode arrastar um slider para alterar a quantidade de parcelas (de 1 a 24) ou o valor da entrada inicial. O motor de cálculo recalcula instantaneamente os juros de parcelamento e o desconto concedido pelo credor de acordo com as faixas configuradas de descontos permitidas.

2. Histórias de Usuário

US-03.1 (Frontend) - Simulador Interativo Visual (Slider)

Como devedor buscando flexibilidade,
Quero alterar o plano de parcelas em uma régua interativa e ver o valor de cada parcela mudar em tempo real,
Para encontrar o ponto de equilíbrio de pagamento que caiba perfeitamente no meu bolso de forma intuitiva.

US-03.2 (Backend) - Motor de Simulação e Desconto Progressivo

Como API do Portal,
Quero aplicar a tabela progressiva de desconto e juros parametrizada por credor a cada simulação enviada pelo front-end,
Para retornar simulações financeiras exatas e homologáveis de acordo com a política de cobrança do credor.

4. Casos de Teste e Validação

Caso Cenário Entrada Resultado Esperado
CT-05 Simulação de pagamento à vista (desconto máximo) installments_requested = 1, down_payment = 0 Retorno de desconto máximo (ex: 60%), juros zero, valor de parcela única = valor negociado à vista.
CT-06 Simulação fora do limite parametrizado pelo credor installments_requested = 48 (limite é 24) Retornar HTTP 422 Unprocessable Entity com a mensagem parametrizada do credor ("Este credor aceita renegociações em até 24 vezes").

FT-04: Checkout, Emissão e Baixa de Pagamentos (Pix & Boleto)

Complexidade de Engenharia Alta
Prioridade de Negócio Crítica
Esforço Estimado 18 Pontos de Feature
Perfis Envolvidos Backend Integration Dev, Devops, QA

1. Descrição do Escopo

Garante o encerramento do acordo negociado. Fornece as rotas de checkout onde o devedor confirma o plano de simulação escolhido. O sistema se integra aos bancos liquidantes para gerar instantaneamente o QR Code Pix e Copia e Cola (preferencial para liquidação instantânea) ou o link/PDF do boleto bancário tradicional de forma segura. Também gerencia os webhooks de confirmação de pagamento para realizar a baixa imediata da negativação no Bureau de Crédito em até 24 horas.

2. Histórias de Usuário

US-04.1 (Frontend) - Finalização Rápida de Acordo via Pix

Como consumidor comprometido a limpar o nome,
Quero fechar meu acordo e obter na mesma tela o QR Code do Pix para pagamento imediato,
Para garantir a liquidação rápida e a exclusão da minha pendência de forma ágil.

US-04.2 (Backend) - Orquestrador de Pagamentos & Sincronizador de Baixa

Como API do Portal,
Quero enviar a transação ao gateway de pagamento bancário, gerar as chaves Pix e boletos e registrar o webhook de conciliação,
Para atualizar o status do acordo no sistema e disparar a limpeza do nome na API de negativação do Bureau.

4. Casos de Teste e Validação

Caso Cenário Entrada Resultado Esperado
CT-07 Webhook recebe evento de pagamento aprovado do Pix Payload de liquidação recebido da API do Banco Status do acordo atualizado para PAID, dispara comando para remover negativação do banco do Bureau, envia SMS confirmando.
