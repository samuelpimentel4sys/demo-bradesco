Modelagem Greenfield

Portal de Autoatendimento de Negociação de Dívidas

Documentação Completa de Casos de Uso (UML / Estrutural) para a engenharia de desenvolvimento e automação de testes do ecossistema de Bureau de Crédito.

Atores do Sistema

👤
Consumidor
Primário

Pessoa física inadimplente buscando consultar pendências financeiras registradas em seu CPF e realizar a quitação/renegociação autônoma das dívidas.

⚙️
Bureau Core
Secundário

Sistema interno do Bureau de Crédito que hospeda a base de dados cadastral oficial, o score de risco de crédito do cidadão e o repositório de negativações ativas.

🏢
Credor Parceiro
Secundário

Instituição credora externa (Banco, Telecom, Varejo) que disponibiliza as dívidas elegíveis e o conjunto dinâmico de regras de descontos e parcelas.

💳
Payment Gateway
Secundário

Provedor de serviços financeiros integrador responsável pela geração instantânea de QR Code Pix, boleto em PDF e notificação de liquidação via webhook.

UC-01Autenticar Consumidor (Acesso Seguro 2FA)

Garante a identificação segura e o sigilo de dados financeiros do consumidor sem requerer senhas estáticas preexistentes.

Prioridade: Crítica Complexidade: Média Feature Associada: FT-01
Pré-condições
  • O consumidor possui um CPF válido.
  • O número de celular ou e-mail correspondente está atualizado na base de dados do Bureau de Crédito.
Pós-condições (Sucesso)
  • Sessão iniciada e Token JWT gerado e guardado localmente (HttpOnly Cookie).
  • Consumidor redirecionado ao painel consolidador.
Fluxo Principal (Caminho Feliz)
Passo Ações do Consumidor Respostas do Sistema
1 Acessa a URL principal do portal e digita o número do seu CPF. Valida a formatação do CPF, verifica se o número existe na base cadastral do Bureau e identifica canais de contato vinculados (celular/e-mail mascarados).
2 Seleciona o canal de preferência (ex: SMS) para recebimento do token e clica em "Receber Código". Gera um código OTP aleatório de 6 dígitos de uso único com expiração de 5 minutos, armazena o hash criptografado na sessão temporária, dispara o SMS via API parceira e redireciona para a tela de verificação.
3 Digita o código de 6 dígitos recebido no celular e clica em "Entrar". Compara o código informado com o código gerado em cache. Ao coincidir, cria um Token JWT seguro com tempo de expiração de 20 minutos, atualiza o timestamp de último acesso e direciona o usuário à dashboard.
Fluxos Alternativos e Exceções
Fluxo Alternativo A: Login via Gov.br Alternativo

Condição: Consumidor prefere autenticar-se com sua identidade cidadã oficial.

No Passo 1, o consumidor clica no botão "Entrar com Gov.br". O sistema redireciona o usuário para o fluxo OAuth do portal oficial do governo. Após o login e autorização do compartilhamento do CPF pelo cidadão, a API do Gov.br devolve o fluxo ao Portal de Autoatendimento com o CPF autenticado. O sistema valida os dados cadastrais locais e gera o token de sessão JWT, pulando a etapa de OTP.

Fluxo de Exceção E1: Código OTP Expirado ou Inválido Exceção

Condição: Código OTP digitado incorretamente ou após 5 minutos de sua geração.

No Passo 3, se o código não coincidir ou o tempo limite estiver ultrapassado, o sistema incrementa o contador de tentativas erradas da sessão, limpa o campo de entrada e exibe a mensagem de alerta correspondente ("Código inválido ou expirado"). Permite até 3 tentativas. Ao atingir o limite, o sistema bloqueia temporariamente novas requisições para o CPF por 15 minutos (mitigação de força bruta).

UC-02Consultar Restrições e Score Cadastral

Carrega na tela do usuário o diagnóstico financeiro integrado, exibindo sua pontuação de crédito atual e os apontamentos de dívidas aptas a serem negociadas.

Prioridade: Crítica Complexidade: Média Feature Associada: FT-02
Pré-condições
  • Sessão do consumidor devidamente autenticada com Token JWT ativo.
Pós-condições (Sucesso)
  • Painel renderizado com a pontuação de score de crédito e o somatório analítico de pendências (originais vs. descontados).
Fluxo Principal (Caminho Feliz)
Passo Ações do Consumidor Respostas do Sistema
1 O sistema navega para a rota padrão da Dashboard automaticamente pós-login. Dispara duas requisições paralelas síncronas ao backend para obter a pontuação do score e a lista consolidada de restrições ativas vinculadas ao CPF.
2 Visualiza as informações na tela em formato de cards analíticos. Calcula o total de economia disponível caso todas as dívidas sejam renegociadas e exibe a lista agrupada por Credor com os respectivos descontos.
Fluxos Alternativos e Exceções
Fluxo Alternativo A: Consumidor sem Restrições Ativas Alternativo

Condição: CPF consultado não possui dívidas pendentes com parceiros credores.

Se as APIs internas retornarem vazias para débitos, o sistema exibe uma tela diferenciada comemorativa ("Seu nome está limpo!") destacando o score em cor verde e oferecendo dicas de saúde financeira.

Fluxo de Exceção E1: Indisponibilidade na API do Bureau Exceção

Condição: Tempo de resposta da base de score ultrapassa o limite tolerado (Timeout de 3s).

Se a requisição de score falhar, o sistema exibe um marcador cinza neutro (esqueleto de carregamento) no componente do score com a indicação "Score indisponível no momento", mas mantém ativa a listagem de dívidas que é carregada a partir do cache local resiliente.

UC-03Simular Plano de Renegociação (Slider Dinâmico)

Permite ao consumidor simular dinamicamente diferentes formas de quitação e planos de parcelamento, adaptando os valores aos limites do seu orçamento.

Prioridade: Crítica Complexidade: Alta Feature Associada: FT-03
Pré-condições
  • O consumidor selecionou uma dívida elegível na Dashboard.
  • As parametrizações vigentes de desconto do credor correspondente estão carregadas no cache do backend.
Pós-condições (Sucesso)
  • Uma proposta comercial de acordo é formalizada temporariamente no sistema, gerando um ID de simulação ativo.
Fluxo Principal (Caminho Feliz)
Passo Ações do Consumidor Respostas do Sistema
1 Clica em "Negociar" sobre uma dívida específica da listagem. Apresenta a tela do Simulador com a opção "Pagar à Vista" selecionada por padrão, aplicando o desconto máximo elegível fornecido pelas regras de negócio.
2 Arrasta o slider para a opção parcelada ou digita um valor de entrada personalizado. Envia uma requisição assíncrona (debounce de 300ms) contendo a quantidade de parcelas e o valor de entrada ao motor de cálculo. O motor aplica a taxa de juros do credor, gera as parcelas e devolve os valores atualizados.
3 Clica em "Visualizar Proposta de Acordo". Valida o plano contra as regras mínimas do credor, salva a proposta com status de "PROSPECT" e apresenta o resumo detalhado para aprovação do devedor.
Fluxos Alternativos e Exceções
Fluxo Alternativo A: Alteração de Entrada com Regra Customizada Alternativo

Condição: Consumidor altera manualmente o valor de entrada para amortização.

No Passo 2, se o consumidor digitar um valor de entrada maior que o mínimo exigido, o motor calcula automaticamente o desconto progressivo sobre as parcelas subsequentes, reduzindo os encargos globais de juros e o saldo devedor financiado, exibindo o aviso "Maior entrada reduz taxas de juros".

Fluxo de Exceção E1: Parcela Abaixo do Mínimo do Credor Exceção

Condição: A divisão simula parcelas com valor individual menor do que o limite definido pelo Credor (ex: R$ 50,00).

No Passo 2, se o valor resultante da parcela for inferior ao mínimo da política do credor, o sistema limita visualmente a progressão do slider, trava a opção e apresenta o alerta: "O número máximo de parcelas para este valor é de X vezes devido ao valor mínimo de R$ 50,00 por parcela".

UC-04Confirmar Acordo de Dívida e Emitir Guia

Conclui formalmente a negociação do débito no sistema e disponibiliza imediatamente as vias de pagamento para o devedor.

Prioridade: Crítica Complexidade: Alta Feature Associada: FT-04
Pré-condições
  • O consumidor possui uma simulação ativa e validada.
Pós-condições (Sucesso)
  • Termo de compromisso assinado digitalmente com aceite dos termos de uso do portal.
  • Guia Pix (QR Code/Copia e Cola) ou boleto em PDF gerado no Gateway de Pagamento e exibido em tela.
Fluxo Principal (Caminho Feliz)
Passo Ações do Consumidor Respostas do Sistema
1 Clica em "Confirmar Acordo com Pagamento Pix" para gerar a liquidação rápida. Valida o ID da simulação, verifica se o prazo de expiração financeira ainda é vigente e envia a requisição de geração de cobrança Pix imediata ao Gateway de Pagamentos.
2 Lê os termos de compromisso de renegociação e clica em "Aceitar e Confirmar". Gera o registro oficial do Acordo com o status de "AWAITING_PAYMENT", retorna o código copia e cola Pix e o QR Code gerado pelo Gateway, e inicia o pooling de monitoramento de status da transação no frontend.
Fluxos Alternativos e Exceções
Fluxo Alternativo A: Emissão em Formato de Boleto Bancário Alternativo

Condição: Consumidor prefere efetuar o pagamento através de boleto bancário.

No Passo 1, se o consumidor escolher "Pagar via Boleto", o sistema realiza a chamada ao Gateway para emissão do boleto de cobrança com vencimento estendido de 3 dias úteis. Em vez de gerar o QR Code imediato Pix, o sistema disponibiliza o código de barras digitável para cópia e o link direto para download do documento em PDF.

Fluxo de Exceção E1: Timeout de Resposta do Gateway de Pagamento Exceção

Condição: Falha de comunicação ou timeout no consumo das APIs do Gateway.

No Passo 2, se o Gateway falhar ao emitir a cobrança, o sistema desfaz a pré-reserva do acordo, exibe o modal de erro avisando: "Não conseguimos gerar sua chave Pix no momento. Não se preocupe, sua proposta está salva! Tente reemitir em alguns minutos", e dispara um log prioritário com payload de falha ao time técnico.

UC-05Conciliar Pagamento e Dar Baixa na Restrição (Assíncrono)

Sistema recebe confirmação bancária do pagamento e inicia os fluxos automáticos de baixa do débito junto ao credor e atualização de cadastro de restrição do Bureau.

Prioridade: Crítica Complexidade: Alta Feature Associada: FT-04
Pré-condições
  • O acordo foi gerado sob o status "AWAITING_PAYMENT".
  • O consumidor efetuou o pagamento no seu banco de origem.
Pós-condições (Sucesso)
  • Acordo marcado como "PAID".
  • Dívida excluída das restrições ativas do CPF no banco de dados em até 24h.
  • Comprovante de quitação disparado para o e-mail cadastrado.
Fluxo Principal (Caminho Feliz)
Passo Ações do Gateway (Webhook) Respostas do Sistema (Backend)
1 Gateway de Pagamentos dispara um webhook `POST /api/v1/payments/webhook` avisando a liquidação do Pix. Verifica a assinatura de segurança do payload do webhook, identifica o ID do acordo associado e altera o status do acordo para "PAID".
2 Envia confirmação assíncrona (OK 200) para o Gateway de Pagamentos. Dispara um evento de barramento interno (Broker):
1. API Bureau Core: Agenda a remoção imediata da restrição do CPF (limpeza do nome).
2. API Credor Parceiro: Envia a notificação da liquidação do acordo.
3. Notification Service: Envia e-mail e SMS de parabéns ao consumidor.
Fluxos Alternativos e Exceções
Fluxo Alternativo A: Conciliação de Boletos via Arquivo de Retorno Alternativo

Condição: Acordo pago via Boleto Bancário (prazo de compensação em até 48 horas).

O Gateway de Pagamentos envia um arquivo consolidado de retorno bancário (CNAB 240) contendo as compensações. O sistema processa o arquivo no lote diário noturno, localiza o acordo correspondente pelo ID da cobrança e segue os passos normais de conciliação e eventos assíncronos de baixa.

Fluxo de Exceção E1: Falha na Comunicação de Baixa com o Bureau Core Exceção

Condição: Indisponibilidade temporária na fila do barramento para o Bureau Core.

Se o microsserviço falhar ao atualizar o cadastro de restrição do Bureau Core, o sistema retém o evento de baixa no broker de mensagens (RabbitMQ / SQS) sob uma política de retry exponencial (até 5 tentativas em 2 horas). Caso esgote, move a mensagem para a Dead-Letter Queue (DLQ), emitindo um alerta prioritário para a equipe de monitoramento de Ops para intervenção manual (garantindo o SLA de remoção em até 24h).
